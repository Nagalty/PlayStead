# Provider Game Metadata Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or superpowers:subagent-driven-development) to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add a provider-neutral, persistable game-metadata snapshot sourced from Steam's existing local `appinfo.vdf` integration, without changing Home or suggestion behavior.

**Architecture:** Core owns the immutable metadata model, tri-state field-presence contract, provider-neutral source/store interfaces, and reconciliation merge semantics. The Steam provider adapts existing local appinfo parsing into those contracts. Data owns an additive SQLite snapshot table and the UI bootstrap composes one reconciliation service into the existing startup/refresh flow.

**Tech Stack:** C#/.NET 10, SQLite through `Microsoft.Data.Sqlite`, existing Valve KeyValue parser, xUnit, Microsoft.Extensions.DependencyInjection/Hosting.

**Spec:** `docs/superpowers/specs/2026-09-24-playstead-0.4.3-provider-game-metadata-design.md`

## Global Constraints

- Keep provider game metadata separate from `ProviderActivityMetadata` and `provider_activity_metadata`.
- Use the existing local Steam `appcache/appinfo.vdf` path; do not add web scraping, AppId hardcoding, a second library scanner, or polling.
- Keep Home UI and Suggestion du moment selection out of this task.
- Preserve unknown values; do not convert unknown capabilities or fields to `false` or empty collections.
- Use migration `013_provider_game_metadata.sql` additively and preserve existing databases.
- Provider failure preserves the previous metadata and freshness timestamp and does not block startup.
- No WPF launch, staging, commit or push during implementation or validation.

## Review Focus

- **Partial provider fields:** `NotReported` must preserve stored values while `ExplicitUnknown` clears them; test this in the reconciliation task.
- **Collection presence:** absent and explicitly empty collections have different meanings; test both in the reconciliation/store task.
- **Tri-state coop:** `SupportsCoop` must return nullable `bool`, especially for one-known/one-unknown combinations; test every combination in Core.
- **Freshness-only refresh:** a new `RefreshedAtUtc` is persisted without a semantic `Changed` event; test timestamp and event independently.
- **Malformed/offline Steam data:** partial appinfo parsing and provider exceptions must preserve prior snapshots and let startup continue; test provider and bootstrap boundaries.

### Task 4: Implement reconciliation merge and notification semantics

**Files:**
- Create: `src/PlayStead.Core/ProviderGameMetadata/ProviderGameMetadataReconciliationService.cs`
- Create: `tests/PlayStead.Core.Tests/ProviderGameMetadata/ProviderGameMetadataReconciliationTests.cs`
- Modify: `src/PlayStead.Data/ProviderGameMetadata/SqliteProviderGameMetadataStore.cs` only for the atomic merge/upsert operation used by reconciliation.

**Interfaces:**
- `ProviderGameMetadataReconciliationService.Changed` emits once after semantic metadata changes.
- `RefreshAsync(LibrarySnapshot snapshot, CancellationToken cancellationToken)` loads previous snapshots, applies `ProviderField<T>` merge rules, and writes through the store.

- [ ] **Step 1: Write RED merge tests**
  - `NotReported` preserves every existing scalar/capability and collection.
  - `Value(T)` replaces the stored value.
  - `ExplicitUnknown` clears the stored scalar/capability.
  - For `Genres`, `Categories`, `Developers` and `Publishers`, `ExplicitUnknown` persists an unknown/null collection and never an empty collection.
  - `NotReported` preserves an existing collection; `Value(empty)` clears it to an explicit empty collection.
  - Malformed/unparseable release dates, scalar values and collection payloads are treated as `NotReported` for that refresh, preserving the last reliable persisted value; they never become `ExplicitUnknown`.
- [ ] **Step 2: Write RED freshness/event tests**
  - Semantic change persists new metadata and timestamp and emits one `Changed` event.
  - Identical metadata updates only `RefreshedAtUtc` and emits no `Changed` event.
  - Provider exception preserves both metadata and freshness and emits no event.
  - Cancellation propagates without a partial success.
- [ ] **Step 3: Implement merge and comparison**
  - Compare semantic fields independently from `RefreshedAtUtc`.
  - Persist semantic and freshness-only successful refreshes atomically; emit only semantic changes.
  - Catch ordinary provider failures per source, retain the last snapshot, and continue other sources.
- [ ] **Step 4: Run Core reconciliation tests**
  - Run `dotnet test tests/PlayStead.Core.Tests/PlayStead.Core.Tests.csproj -c Release --no-restore --filter "FullyQualifiedName~ProviderGameMetadataReconciliation"`.

**Acceptance:** All three presence states merge correctly for scalars and collections, including `ExplicitUnknown` as persisted null/unknown rather than empty; malformed values are `NotReported` and preserve last-known state; freshness-only writes are silent, semantic changes notify once, and failures preserve last-known state.
