# PlayStead 33A Multi-Channel Update Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add provider-neutral update contracts and build-channel strategy composition for GitHub and Microsoft Store without downloading or installing updates.

**Architecture:** `PlayStead.Core` owns the channel enum, common state/action model, service contract, and strict GitHub manifest model. `PlayStead.Providers` owns GitHub/Store strategy implementations. `PlayStead.UI` injects the build channel, composes exactly one strategy, and schedules a post-Ready background check.

**Tech Stack:** .NET 10, WPF, Microsoft.Extensions.Hosting/DI, existing PlayStead Core/Providers/UI projects, xUnit.

**Spec:** `docs/superpowers/specs/2026-09-27-playstead-0.4.3-task33a-update-architecture-design.md`

## Global Constraints

- Do not launch WPF.
- Do not stage, commit, or push.
- Do not add a Microsoft Store ProductId until a real ProductId exists.
- Do not add network calls, downloads, hashing, updater, replacement, or relaunch behavior.
- Keep update checks post-Ready and off the critical startup path.
- Keep the functional version independent from `DistributionChannel`.
- Do not implement 33B+ UI or installation behavior.

## Review Focus

- Unknown/unset channel metadata must fail safely to the current default channel and be covered by channel-resolution tests.
- GitHub manifest malformed URLs, versions, hashes, and missing required fields must be rejected without network access.
- Store strategy without a ProductId must return a non-actionable state and must not fabricate a URI.
- Strategy selection must resolve exactly one implementation and never cross-call the other channel.
- Post-Ready update checking must not delay the Ready transition and must contain service failures.

## Completion criteria

33A is complete when one channel is selected from build metadata, one common update service is composed, both strategy contracts are covered without real network/package operations, the check starts only after Ready, no Store ProductId is invented, and all requested validations pass or are reported with concrete lock evidence.
