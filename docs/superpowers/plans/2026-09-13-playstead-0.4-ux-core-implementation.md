# PlayStead 0.4 UX Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver PlayStead 0.4 as the first visually mature UX-core milestone: Dark Copper design system, horizontal top navigation, contextual Home, virtualized Library, quick panel, progressive game detail, local global search, minimal Play action, Attention surface, redesigned Sessions, UI-state persistence, reduced motion, and final runtime/performance acceptance without regressing the 0.1–0.3 guarantees.

**Architecture:** Keep PlayStead as the existing single-process Windows WPF application. The majority of 0.4 work stays in `PlayStead.UI`; presentation state is expressed through small MVVM view models and adapters, while platform-specific launch behavior is isolated behind a narrow service. Existing Core/Data/Platform/Providers contracts are preserved unless a Task proves a missing API is required. Navigation uses a single shell route service and a back stack; Library context is held independently so opening a game and returning restores grid/list mode, sort/filter/search state, selected item, and scroll offset.

**Tech Stack:** C# / .NET 10 / WPF + XAML / MVVM / SQLite and local files already present / xUnit / Generic Host.

**Spec:** `docs/superpowers/specs/2026-09-13-playstead-0.4-ux-core-design.md`
