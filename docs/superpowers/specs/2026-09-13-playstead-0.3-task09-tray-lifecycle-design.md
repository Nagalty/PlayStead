# PlayStead 0.3 — Task 09 Tray & WPF Lifecycle Design

## Goal

Keep PlayStead running in the Windows notification area when the main window is closed, provide explicit Open/Quit tray commands, preserve single-instance restoration, expose current session activity in the tray tooltip, and ensure the session monitor cannot touch SQLite before database migrations complete.

## Startup safety

The Generic Host is built before local state initialization so dependency injection is available, but it is not started yet. The startup order is authoritative:

1. parse invocation;
2. acquire the single-instance gate;
3. create the user-data layout and directories;
4. build the Generic Host without starting hosted services;
5. run `LocalStartupPipeline.InitializeAsync` so migrations, health check, cached library, and cached Steam reference are ready;
6. abort without starting hosted services if the database is unhealthy;
7. start the Generic Host;
8. show the cached UI;
9. bind invocation/rescan handlers and launch background refresh.

`SessionMonitor` remains an `IHostedService`. The safety property comes from starting the host only after local database initialization.

`ApplicationStartupCoordinator.Operations` therefore exposes two distinct operations:

```csharp
Func<UserDataLayout, CancellationToken, Task> BuildHostAsync
Func<CancellationToken, Task> StartHostAsync
```

`StopHostAsync` must dispose a built-but-never-started host safely as well as stop/dispose a started host.

## Close-to-tray lifecycle

`App.xaml` uses `ShutdownMode="OnExplicitShutdown"`.

A singleton `WindowClosePolicy` tracks whether a real application exit was explicitly requested:

```csharp
public bool IsExitRequested { get; }
public void RequestExit();
```

The DI-created `MainWindow` receives this policy. On normal close:

1. capture/save window placement exactly as today;
2. cancel the close;
3. hide the window.

When `IsExitRequested` is true, `MainWindow` allows the close to continue.

Direct test-only `MainWindow` constructors that do not receive the policy retain ordinary close semantics.

## Tray service

`PlayStead.UI` enables WinForms interop with `<UseWindowsForms>true</UseWindowsForms>` and uses the native `System.Windows.Forms.NotifyIcon`.

Create:

- `PlayStead.UI.Tray.WindowClosePolicy`
- `PlayStead.UI.Tray.TrayStatusText`
- `PlayStead.UI.Tray.TrayIconService`

`TrayIconService` is a DI singleton. Its stable public contract is:

```csharp
public event EventHandler? ExitRequested;
public void Start();
public Task OpenAsync(CancellationToken cancellationToken);
public void RequestExit();
public void UpdateSessionCount(int activeSessionCount);
```

`Start()` creates/shows the notify icon, installs a context menu containing `Ouvrir PlayStead` and `Quitter PlayStead`, wires double-click to `OpenAsync`, subscribes to session snapshot updates, and initializes the tooltip from the latest known snapshot.

`OpenAsync` delegates to the existing `IWindowActivator`, preserving current hidden/minimized window restoration and second-instance foreground behavior.

`RequestExit` first calls `WindowClosePolicy.RequestExit()` and then raises `ExitRequested`. `App` handles `ExitRequested` by calling `Shutdown()`.

`TrayIconService.Dispose()` unsubscribes from session updates, hides the icon, and disposes native tray resources.

## Session status publication

`SessionMonitor` keeps:

```csharp
public SessionRuntimeSnapshot? LatestSnapshot { get; private set; }
public event Action<SessionRuntimeSnapshot>? SnapshotUpdated;
```

After every successful `ISessionRuntime.RefreshAsync`, it updates `LatestSnapshot` and publishes `SnapshotUpdated`.

The tray tooltip is deliberately small and local-only:

- `PlayStead — aucune session active`
- `PlayStead — 1 session active`
- `PlayStead — N sessions actives`

No game names, process paths, analytics, or remote transmission are added.

## Composition

`PlaySteadHost` registers `WindowClosePolicy` and `TrayIconService` as singletons.

After a successful `ApplicationStartupCoordinator.StartAsync`, `App` resolves `TrayIconService`, subscribes to `ExitRequested`, and calls `Start()`.

The existing named-pipe/single-instance flow is retained. A second invocation still reaches `MainWindowActivator`, which already shows a hidden window, restores a minimized window, and activates it.

## Tests

Task 09 RED/GREEN coverage includes:

- coordinator source order: build host → initialize local state → start host;
- App split between host build and host start;
- explicit WPF shutdown mode;
- WinForms tray interop enabled;
- tray/close-policy DI registration and public contract;
- normal host-created window close hides and remains showable;
- session monitor publishes and retains its latest snapshot;
- tray status text for 0/1/N sessions;
- existing single-instance, window-placement, session-monitor, Core/Data/UI regressions remain green.

Advanced analytics, custom tray artwork, notifications/toasts, autostart, and settings are out of scope.
